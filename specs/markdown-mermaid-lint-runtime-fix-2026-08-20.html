Markdown Mermaid lintの実行時互換性修正

Mermaid 11.16.1をNode.jsまたはBunから直接読み込むと、DOMを持たない実行環境ではDOMPurifyが未初期化のfactoryとして残る。ラベルのサニタイズを行う正常な図でDOMPurify.addHook is not a functionが発生し、lintが誤ってMD003を報告していた。

決定

Markdown lintがMermaidを最初に読み込む間だけ、jsdomで作った隔離DOMをglobalへ公開する。import後はglobalを元のproperty descriptorへ戻してDOMを閉じる。初期化済みMermaid parserはprocess内で再利用し、文書ごとのDOM生成とglobal変更を避ける。

挙動と依存関係

修正後のMarkdown Mermaid lint契約
条件 結果
Mermaid導入済み・正常な図 診断なし。ラベルを含むflowchart、class diagramを回帰テスト対象にする。
Mermaid導入済み・不正な図 MD003を報告する。
Mermaid未導入・Mermaid fenceあり optional packageの導入が必要であることを英語で示し、運用エラーとして終了code 2を返す。

jsdomはlint実行時に必要なためruntime dependencyへ移す。Viewer側のMermaidは引き続きoptional peer dependencyとし、図を含まないprojectでは読み込まない。

検証条件

  • Node.js 24.11.1とBun 1.3.14で、ラベル付きの正常図がlintを通過する。
  • 不正な図は引き続きMD003になる。
  • 存在しないlint対象directoryのCLIエラーは英語になる。
  • package後のconsumer環境でも同じ結果になる。
