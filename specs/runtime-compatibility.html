Runtime compatibility

Support policy

Spec HTMLは、対象directoryへ設定fileや初期化codeを追加せず、対応runtimeだけでinstall、build、test、Viewer起動まで実行できることを保証する。

対応runtimeとCIでの検証範囲
Runtime Minimum version CI verification
Node.js 20 20.19.0 clean install、typecheck、unit/server test、build、consumer package test
Node.js 22 22.16.0 clean install、typecheck、unit/server test、build、consumer package test
Node.js 24 24.0.0 全check、Chromium、Firefox、WebKit、macOS、Windows
Bun 1.3 Bun runtimeでのtypecheck、unit/server test、build、CLI起動、consumer package test

BunではNode.js用shebangをBun runtimeへ切り替えるため、利用時にbunx --bun spec-htmlを使用する。

Compatibility boundary

  • packageのNode.js engine条件はruntime dependencyが対応する最小minor versionと一致させる。
  • CLI bundleは最小対応Node.jsであるnode20をbuild targetとする。
  • Node.js固有APIを使う場合は、Bunで同等APIがない場合の安全なfallbackをtestする。
  • optional dependencyが存在しない状態でも、通常のHTML表示とViewer起動を成功させる。
  • browser testはNode.js 24で実行し、生成したbrowser assetのruntime互換性はPlaywrightの3 engineで検証する。

Prevented regressions

  • BunでIncomingMessage.headersDistinctがない場合はrawHeadersからHostとOriginを取得し、重複headerの拒否を維持する。
  • Bunのmodule解決errorがErrorを継承しない場合も、error codeでoptional dependency未導入を判定する。
  • filesystem APIの成功時戻り値はruntime間で異なる可能性があるため、testでは値ではなく成功そのものを検証する。
