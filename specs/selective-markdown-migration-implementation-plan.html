選択的Markdown migration実装計画

決定

migrateは、OSSで慣例的にMarkdownとして維持する文書を組み込みで保護し、 content root相対の対象directoryをCLIから選択できるようにする。専用manifestは追加しない。 対象directoryを省略した場合は、従来どおりcontent root全体から保護文書だけを除いて移行する。

組み込み保護対象
basename 扱い
README 常にactive Markdownとして維持する
CONTRIBUTING 常にactive Markdownとして維持する
CHANGELOG 常にactive Markdownとして維持する
SECURITY 常にactive Markdownとして維持する
AGENTS 常にactive Markdownとして維持する

判定は大文字小文字を区別せず、.mdと.markdown、および README.ja.mdのようなbasename直後のvariantを含む。directory位置には依存しないため、 spec/README.mdも保護される。

CLI contract

spec-html migrate ./spec --target architecture --target concepts --lang ja --check
spec-html migrate ./spec --target architecture --target concepts --lang ja --write
  • --targetはcontent root相対のdirectoryであり、複数回指定できる。
  • 指定directoryとその子孫にある、保護対象ではないMarkdownだけを移行する。
  • 絶対path、..、空segment、backslash、content root外、symbolic link、通常directory以外は拒否する。
  • --targetは--checkと--writeだけで使用できる。
  • rollbackとfinalizeはjournalが対象集合を保持するため、対象directoryの再指定を必要としない。

link安全性

生成HTML内と既存HTML内の通常navigation linkは従来どおり安全に書き換える。 保護対象または対象外のMarkdownは編集しない。そのMarkdownからArchive予定sourceへのlinkが残る場合、 virtual post-state lintが壊れた参照としてblockする。利用者は対象範囲の見直し、linkの明示更新、 または元Markdown維持のいずれかを選ぶ。

完了条件

  1. 保護basenameとvariantがtarget内でもArchiveされない。
  2. 複数targetの和集合だけが生成・Archive対象になる。
  3. target外または保護Markdownから移行対象へのlinkが自動編集されず、write前にblockされる。
  4. 遅れてtarget内へ追加された非保護Markdownをcommit直前に検出して全体rollbackする。
  5. 保護・target外Markdownを残した状態でも、期待済みdiagnosticを含む最終project lintが一致する。
  6. 従来のtarget未指定migration、journal、rollback、finalizeが成立する。
