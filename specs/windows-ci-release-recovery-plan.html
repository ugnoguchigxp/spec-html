Windows失敗の原因分離

Log上の失敗と所有者
失敗 原因 分類 対応
convert CLI test /table.htmlを正規表現で固定し、Windowsのbackslashと一致しない。 Project側のtest defect 既知のoutput pathを使った完全一致にする。
fix／format mode test Windowsでも変更後modeをPOSIX 0640と仮定する。実測は0666。 Project側のtest defect 書込前modeを保存し、書込後が同値であることをplatform非依存で検証する。
libuv fs-event.c:72 Node 24.16以降のWindows short／long pathを含むrecursive watcher regression。 Upstream confirmed bug 修正を含むNode releaseまでWindows CIを24.15.0へ固定し、project codeの無根拠な変更は行わない。
packed consumer spawn EINVAL child_process.spawnでWindowsのnpm.cmdを直接起動していた。 Project側のtest defect shellを介さず、process.execPathからnpm-cli.jsを実行する。

libuv assertionはnodejs/node#63638としてconfirmed bugになり、upstream修正はnodejs/node#65118で2026-08-14にmerge済みである。ただし失敗runのWindows runnerはNode 24.19.0で、まだ修正を含んでいない。したがって、retryで隠すのではなく、既知の正常versionへ一時固定する。

修正後の再実行ではWindows jobがpack consumerまで成功した。一方、Node 20 jobで未消費のHTTP responseがserver終了を妨げるSIGKILLも検出したため、全response bodyを消費してからgraceful shutdownするよう併せて修正する。

Phase 1: Windows CIをgreenへ戻す

  1. tests/unit/cli-main.test.tsの生成path assertionを次の契約へ変える。 
    expect(logs).toHaveBeenCalledWith(`Created: ${output}`);
  2. fix／format testではchmod後のmodeを取得し、atomic write後も同値であることを確認する。 
    const beforeChanged = await lstat(changed);
// write operation
expect((await lstat(changed)).mode).toBe(beforeChanged.mode);

    POSIXではchmod(0640)が反映されることも別途確認できるが、WindowsへPOSIX permission semanticsを要求しない。

  3. GitHub ActionsのWindows jobだけNode 24.15.0へ固定する。job名にもpatch versionを表示し、workflow commentへnodejs/node#63638と解除条件を記録する。
  4. 同じcommitをpushし、Windows jobが360 tests、build、packed consumer testまで完走することを確認する。
一時pinの解除条件

Nodeのrelease noteまたは実runでnodejs/node#65118を含むversionを確認した後、Windowsをそのversionへ上げる。24へ即座に戻さず、1回の明示的なcompatibility changeとしてreviewする。

Phase 2: 0.1.1 release準備

  1. CHANGELOG.mdを実際の公開境界で分割する。
    • 先頭へ空のUnreleased sectionを置く。
    • 0.1.1 - 2026-08-19へMarkdown preview、convert、Markdown security hardening、Windows CI portabilityを記載する。
    • 0.1.0 - 2026-08-19には既に公開されたHTML viewer機能だけを残す。
  2. npm version 0.1.1 --no-git-tag-versionでpackage.jsonとpackage-lock.jsonを同時更新する。
  3. npm metadataを新しい製品scopeへ合わせる。descriptionへHTMLとMarkdownを含め、keywordsへmarkdownとconversionを追加する。
  4. README英日版のNode要件矛盾を解消する。RequirementsのNode 20.19／22.16／24対応を正とし、limitationsの「24未満は非対応」を削除する。
  5. release guideの「初回公開前」を通常のregistry preflightへ更新し、対象versionが未公開であることをreleaseごとに確認する。

再発防止

手順書だけでなく、明示的なrelease:check commandを追加する価値がある。networkを必要とするためprepackや通常のcheckへは混ぜず、maintainerがrelease直前に実行する。

推奨commit分割

  1. fix: restore Windows CI portability — test assertionとNode一時pinだけ。
  2. chore: add release consistency checks — release guideとrelease:check。
  3. chore: prepare 0.1.1 release — version、changelog、metadata、README整合。

この順序なら、Windows修正の成否をrelease metadata変更から切り離せる。公開操作、tag、GitHub Releaseはcommitには含めず、最後のmaintainer手順として実行する。

今回行わないこと

  • 公開済み0.1.0の上書きまたはunpublish
  • upstream libuv bugを推測で回避するproduction watcherの大規模変更
  • Windows jobのretryやcontinue-on-errorによるfailureの隠蔽
  • Markdown lint、bundle分割、navigation cacheなど次release向け機能改善
  • CIからの自動npm publishへの移行
