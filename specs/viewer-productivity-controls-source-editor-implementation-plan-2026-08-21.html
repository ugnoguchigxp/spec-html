HTMLビューア操作支援・ソース編集機能 実装計画

HTMLビューアに、ページ先頭へ戻るフローティングボタン、表示中ドキュメントのパスコピー、 実行時に生成する小型目次、HTML・Markdownソースの編集保存を追加する。 既存のiframeプレビュー、ドキュメント操作メニュー、ライブリロード、安全な原子的書き込みを活用し、 新しい依存ライブラリは追加しない。

結論: 4機能とも実装可能である。相対パスはブラウザが保持する現在のドキュメントパスをそのままコピーできる。 絶対パスも実装できるが、ブラウザだけでは取得できないためサーバーから提供する必要がある。 絶対パスはローカルのディレクトリ構成やユーザー名を含み得るため、初期実装ではloopback接続時だけ表示する。

実装結果

この計画に含めた機能は2026-08-21に実装した。

  • iframe内のscroll位置に連動するScroll to topボタンを追加した。
  • 相対パス、loopback接続時の絶対パス、Show outlineを右上メニューへ追加し、Archive・Restoreを常に最下部へ配置した。
  • iframeのh1・h2・h3から実行時ID付きの目次を生成し、右・左・非表示の選択を保存するようにした。
  • 目次表示中はiframeを全幅のまま保ち、iframe内の本文領域に目次幅と余白を確保するため、本文と重ならずscrollbarは常に右端になる。モバイルでは目次を本文の上に配置して、本文の高さを縮める。
  • ソースモーダルを編集可能なtextareaとSaveボタンへ変更し、HTMLとMarkdownを保存できるようにした。
  • GET・PUTのdocument source APIを追加し、SHA-256 revision、content mutation lock、原子的置換、Origin検証、本文上限、409競合応答を実装した。
  • 保存時はライブリロードを一時保留し、PUTの完了後に既存のファイル監視による再表示へ委ねるようにした。
  • server・security・Playwrightテストを追加し、保存、競合、archive済み文書、コピー、目次、スクロール、実ファイルへの保存を検証した。
  • 実装レビューで、読込完了前の入力も未保存変更として扱うようにし、読込中に外部更新を検出した場合は保存を無効化して再オープンを求める保護を追加した。 CRLFだけを使う文書は保存時にもその改行コードを維持する。
  • runtime CSS・JavaScriptの5分キャッシュにより再起動後も旧レイアウトが表示される問題を解消した。起動ごとのversion queryをshellから付与し、runtime assetはno-storeで配信する。

現状の実装と接続点

  • 表示中の相対パスはsrc/browser/start.tsの currentDocumentに正規化済みの値として保持されている。
  • プレビューはsrcdocを使った同一オリジンのiframeであり、親画面から contentDocumentとcontentWindowを操作できる。
  • 右上メニューは現在Archive・Restoreだけを持ち、右下のソースモーダルは preでソースを読み取り専用表示している。
  • サーバーにはArchive・Restore用の更新経路はあるが、ソースを書き込むHTTP APIはまだない。
  • src/content/safe-write.tsには、権限を保った原子的置換、SHA-256ダイジェスト、 通常ファイル確認の部品がある。Archive・migration用の排他ロックも再利用できる。
  • content rootの変更はファイル監視されており、保存後は既存のライブリロードでプレビューを更新できる。

UI・操作仕様

ページ先頭へ戻るボタン

  • iframe内の縦スクロール量が480pxを超えたときだけ表示する。
  • クリック時はiframeのwindow.scrollToを呼び、先頭へ移動する。
  • 通常はsmooth scrollとし、prefers-reduced-motion: reduceでは即時移動する。
  • aria-label="Scroll to top"を設定し、印刷時は非表示にする。
  • ドキュメント切替時に古いiframeのscroll listenerを解除し、新しいiframeへ付け替える。

パスコピー

右上メニューに次の項目を追加する。

  1. Copy relative path: currentDocumentをコピーする。
  2. Copy absolute path: サーバーが返した実ファイルの絶対パスをコピーする。

右上メニュー全体の表示順は次のとおりとする。

  1. Copy relative path
  2. Copy absolute path（利用可能な場合のみ）
  3. Show outline
  4. 区切り線
  5. ArchiveまたはRestore

Archive・Restoreは破壊的または状態変更を伴う操作として他の操作から分離し、 メニュー項目が今後増えた場合も常に一番下へ配置する。

コピー成功時はメニューを閉じて「Copied relative path」または「Copied absolute path」を通常色で短時間表示する。失敗時はメニュー付近にエラー色で表示する。Clipboard APIを第一候補とし、利用できないHTTP環境では 一時的なtextareaを使うフォールバックを設ける。

絶対パスはloopback接続時だけAPI応答に含める。非loopback接続では値をnullにして メニュー項目を表示しない。将来リモート利用で必要になった場合だけ、明示的なCLIオプションを別途追加する。

小型目次

本仕様では「H3以上」を文書階層の上位3段階であるh1・h2・h3と解釈する。 h3からh6を意図していた場合も、抽出selectorを変更するだけで対応できる。

  • iframeの読み込み完了後にh1, h2, h3をDOMから抽出する。
  • 一意な既存idは変更しない。idがない見出し、または重複したidを持つ後続見出しには衝突しない実行時IDを付与する。
  • 実行時IDはiframeのDOMだけに追加し、保存対象のソースには書き戻さない。
  • 目次項目は実際のa href="#..."とし、既存の履歴・hash navigationへ接続する。
  • 同じ見出し名が複数あっても、連番を含むIDで個別に移動できる。
  • 右上メニューの「Show outline」で再表示でき、パネル内のLeft・Right・Close操作で位置を変える。
  • 位置はright・left・hiddenの3値で保存し、初期値はrightとする。
  • パネルは幅240px程度、最大高60vhとし、本文のレイアウトを押し広げずプレビュー上に重ねる。
  • デスクトップではiframeを全幅に保ち、表示中の目次位置に応じてiframe内のdocument rootの左または右へ272pxを確保する。本文がパネルの背後へ入らず、iframeのscrollbarは画面右端に残る。非表示時と見出しがない文書では確保しない。
  • 幅767px以下では、目次をiframeの上に通常フローで配置する。目次の高さだけiframeを縮め、本文や目次が重ならないようにする。
  • 対象見出しがない文書ではパネルを表示せず、メニュー項目を無効化する。

ソース編集モーダル

  • 既存のpreを等幅フォントのtextareaへ置き換え、モーダルを開いた直後から編集可能にする。
  • HTMLだけでなく、既存仕様どおりMarkdownドキュメントではMarkdownソースを編集する。
  • ヘッダーまたはフッターにSaveボタン、保存状態、Closeボタンを置く。
  • 未変更時はSaveを無効化し、入力後に有効化する。保存中は二重送信を防ぐ。
  • 未保存の変更がある状態でEscape・Close・履歴移動・ページ離脱を行う場合は破棄確認を表示する。
  • 保存成功後はモーダルを閉じ、ライブリロードを1回だけ行ってプレビューと目次を再生成する。
  • 保存失敗時はモーダルを閉じず、入力内容を保持したまま原因を表示する。
  • 外部エディタで同じファイルが変更されていた場合は上書きせず、競合メッセージを表示する。
  • ダイアログを開いた直後に入力され、続いて取得した最新ソースが初期表示と異なる場合も保存しない。入力内容を表示したまま、閉じて再オープンして最新ソースから編集し直すよう案内する。
  • textareaで正規化される改行コードによって未変更と誤判定しない。元ファイルがCRLFのみを使う場合、保存する内容もCRLFに戻す。

保存APIとデータ整合性

新しい/_spec-html/document-source?doc=...エンドポイントを追加する。 プレビュー本文の画像・相対リンク用には従来どおり/_content/ URLを使う。

document source APIのHTTP操作、要求、応答
操作 要求 応答
GET 正規化済みの相対doc doc、format、source、revision、条件付きabsolutePath
PUT sourceとexpectedRevisionを持つJSON 保存後のdocと新しいrevision

revisionはUTF-8ソースのSHA-256ダイジェストとする。PUT時に実ファイルの現在値と expectedRevisionが一致しなければ409 Conflictを返す。 これにより、モーダルを開いた後に外部エディタが行った変更を誤って消さない。

サーバー側の安全条件

  • 既存のnormalizeDocumentPathで絶対パス、親参照、バックスラッシュ、不正な拡張子を拒否する。
  • 一覧探索で確認できるactiveまたはarchivedの通常ファイルだけを編集対象とし、symlinkは拒否する。
  • activeとarchivedの両方に同名ファイルがある場合は競合として保存しない。
  • Archive・migration・ソース保存で同じcontent mutation lockを使う。
  • 既存のatomicReplaceで元ファイルのmodeを保ち、同一ディレクトリ内の一時ファイルから置換する。
  • PUTは既存のdocument state更新と同じOrigin検証を必須にする。
  • JSON本文には上限を設け、上限超過は413 Payload Too Largeにする。
  • UTF-8文字列として保存し、HTMLやMarkdownの構文エラーだけを理由に保存を拒否しない。
  • 絶対パスはloopback接続に限って返し、ログやエラーメッセージへ不要に含めない。

ライブリロードとの協調

現状はファイル変更イベントを受けると即座にページを再読み込みするため、PUTの応答前に画面が更新される可能性がある。 installLiveReloadからcontrollerを返す形に変更し、保存中だけreloadを保留する。 保存成功後は保留中のreloadを1回実行し、失敗時は編集内容を残したまま外部変更分のreloadだけを通知する。

実装順序

  1. 読み取り専用の操作支援: 先頭へ戻るボタン、相対パスコピー、目次抽出・移動・位置保持を実装する。
  2. document source API: 通常・archivedファイルの安全な解決、GET snapshot、PUT保存、revision競合を実装する。
  3. 編集UI: textarea、dirty状態、保存、離脱確認、エラー表示、ライブリロード保留を接続する。
  4. 絶対パス: loopback判定とAPI応答を追加し、利用可能な場合だけコピー項目を表示する。
  5. 回帰確認: mobile、dark mode、print、Archive・Restore、Markdown、Mermaid、Chart.jsを確認する。

テスト計画

Unit・server

  • 通常ファイルとarchivedファイルのsource snapshotを取得できる。
  • 正しいrevisionなら保存され、modeが維持され、新しいrevisionが返る。
  • revision不一致、active・archived競合、symlink、不正パス、対象なしを拒否する。
  • cross-origin PUT、JSON以外、本文上限超過、未許可methodを拒否する。
  • 非loopbackでは絶対パスを返さない。
  • Archiveまたはmigrationの処理中に競合する保存を安全に失敗させる。

Playwright

  • 長い文書をスクロールするとボタンが現れ、クリックでiframe先頭へ戻る。
  • 相対パスと、loopback時の絶対パスをクリップボードへコピーできる。
  • IDのない見出しを含む目次から目的位置へ移動できる。
  • 右・左・非表示を切り替え、再読み込み後も設定が維持される。
  • HTMLとMarkdownのソースが最初から編集可能で、Save後に実ファイルとプレビューが更新される。
  • 未保存の変更を閉じようとすると確認され、保存失敗時は入力内容が残る。
  • 外部変更後のSaveが409となり、外部変更を上書きしない。
  • 目次とフローティング操作が印刷時に表示されない。

受け入れ条件

  • 表示中のdocumentがない状態では、追加した操作を実行できない。
  • 4機能がキーボードだけで操作でき、focus表示とaccessible nameを持つ。
  • 右上メニューではArchiveまたはRestoreが常に一番下に表示される。
  • 目次のために元ソースへIDを自動保存しない。
  • 保存は明示的なSave操作でのみ発生し、未変更のファイルを書き換えない。
  • 外部変更、Archive、migrationとの競合時に既存ファイルを失わない。
  • 既存の閲覧、navigation、Archive・Restore、theme、print、ライブリロードが回帰しない。
