Authoring guide

このguideは、LLMが通常Markdownで生成する設計書や仕様書を、Markdown以上の表現力と読みやすさを持つ構造的なHTML fragmentとして生成・編集する方法を定めます。LLMには完全なWeb pageや独自componentではなく、標準のsemantic HTMLで本文を直接生成させます。Viewerと生成文書はローカルの信頼済み環境だけで利用し、公開serviceへのhostingを前提にしません。

LLM authoring workflow

LLMへの依頼には、本文をMarkdownではなく構造的なHTML fragmentで出力し、後述のDocument authoring principlesへ適合させることを指定します。Navigationはcontent directoryから実行時に構成されるため、複数文書を作る場合もメニューfileの更新は不要です。

Spec HTMLは既存のMarkdownを機械的にHTMLへ変換するtoolではありません。LLMが構造的なHTMLを直接生成し、共通Viewerが一貫した見栄えを与えることで、Markdownでは扱いにくい表現を使いながら文書ごとのCSS作成を減らします。

Document authoring principles

Spec HTMLは、独自の文書DSLではなく、標準HTMLをそのまま本文形式として使用します。要素ごとの許可listは設けず、HTML Living Standardで本文に使用できる要素を、本来の意味に従って自由に使用します。project固有の制約は次の最小限に留めます。

  • 各設計書fileは、文書の主言語をlangで示した1つのarticleをrootとするHTML fragmentにします。Viewerが生成するhtml、head、bodyなどの文書外枠は含めません。
  • 文書には1つのh1を置き、見出しlevelを飛ばしません。それ以外の標準要素は、内容に合う意味を持つものを選びます。
  • 適切なsemantic elementがある場合は、divやspanで代用しません。pは意味の薄い汎用containerではなく、文章の段落に使用します。
  • specificationやspec-documentのような独自要素は使用しません。標準HTMLにないdomain上の分類が必要な場合は、articleやsectionなどの標準要素へdata-*属性を追加し、同じ情報を本文にも表示します。
  • scriptはchartなどの表示を強化する目的に限定します。要件、数値、結論、警告などの重要な内容は、JavaScriptを実行しなくてもHTML本文から取得できるようにします。

標準HTMLの仕様やaccessibility要件を、このguideで要素ごとに再定義しません。詳細な書き方は標準仕様に従い、このprojectでは規約の追加よりもsemantic HTMLの例と自動検証で品質を担保します。

Content directory

Viewerへ渡すdirectoryには、任意数のHTML fragmentを置きます。画像などのassetは同じdirectoryの配下へ置いてください。

specs/
├─ overview.html
├─ api/
│  └─ endpoints.html
└─ assets/
   └─ architecture.svg

Navigation

Viewerはcontent directory内の拡張子が.htmlのfileを再帰的に読み取り、directoryごとにまとめたnavigationを実行時に構成します。各linkの表示名には文書内で最初に見つかったh1を使用し、h1が空または存在しない場合はfile名を使用します。

隠しdirectoryとnode_modulesは探索対象外です。Navigationはbrowserを開くたびに現在のdirectoryから構成され、repositoryへメニュー用fileを保存しません。起動中は指定directory配下の変更を監視し、文書や画像を変更・追加・削除するとbrowserを自動reloadします。表示可能なHTMLがない場合、Viewerは案内messageを表示します。

HTML fragments

各fileはDOCTYPEやhtml、head、bodyを持つ完全なHTML documentではなく、本文fragmentとして記述します。最初のh1がViewerのdocument titleになります。

<article lang="en">
  <header>
    <h1>API endpoints</h1>
    <p>Public endpoint definitions.</p>
  </header>

  <section id="errors">
    <h2>Errors</h2>
    <p>Errors use the problem details format.</p>
  </section>
</article>

文書間linkとasset URLは、現在表示しているHTML fileを基準に解決されます。

<a href="../overview.html#authentication">Authentication overview</a>
<img src="../assets/architecture.svg" alt="System architecture">

Semantic styles and callouts

Viewerは見出し、list、table、code、blockquote、details、figureなどへ既定styleを適用します。Sidebar上部のspec-htmlラベル横にある「Light」「Auto」「Dark」から表示themeを選択でき、「Auto」はOS設定へ追従します。選択内容はbrowserへ保存され、dark表示はTokyo Night Stormを参考にした青みのあるpaletteです。Sidebar幅を超える文書タイトルは末尾を省略表示し、hover時のtooltipで全文を確認できます。画像、SVG、canvas、video、audioは文書幅を超えません。インライン画像とSVGは文章内にも配置できます。

補足にはasideを使用できます。視覚的な種類はdata-typeへwarning、danger、successのいずれかを指定します。属性を省略した場合はnote表示です。支援技術でも内容を識別できるよう、見出しへIDを付けてaria-labelledbyから参照してください。

<aside data-type="danger" aria-labelledby="delete-warning">
  <h3 id="delete-warning">削除に関する警告</h3>
  <p>この操作は取り消せません。</p>
</aside>

Browserの印刷機能を使用すると、Sidebarとmobile menu buttonを除いた現在の文書をlight配色で印刷します。閉じているdetailsの内容も印刷対象です。

Mermaid

利用projectへmermaidをインストールし、diagram sourceを.mermaid要素へ直接記述します。

<figure>
  <pre class="mermaid">
  flowchart LR
    Browser --> API
    API --> Database
  </pre>
  <figcaption>Request processing flow</figcaption>
</figure>

Viewerはページ表示時にdiagramを描画します。生成済みSVGをrepositoryへ保存する工程は不要なので、頻繁な仕様変更でもHTML内のdiagram sourceだけを更新できます。Mermaidが未導入の場合は描画処理を読み込みません。themeはSidebarで選択した表示へ追従し、「Auto」の場合はOS設定変更時にも現在の文書を再読み込みして描画し直します。

Chart.js

利用projectへchart.jsをインストールすると、fragmentのinline scriptからglobalのChartを使用できます。

<figure>
  <canvas id="request-count" aria-describedby="request-count-caption"></canvas>
  <figcaption id="request-count-caption">
    Request count: GET 120, POST 35.
  </figcaption>
</figure>
<script>
  new Chart(document.getElementById("request-count"), {
    type: "bar",
    data: {
      labels: ["GET", "POST"],
      datasets: [{ label: "Requests", data: [120, 35] }]
    }
  });
</script>

DOM上のIDは同じfragment内で一意にしてください。Chart.jsが未導入の場合、Chartを参照するscriptは書かないでください。

Trust boundary

fragment内のinline scriptは実行されます。Spec HTMLはsanitizerではありません。内容を信頼できないHTMLや、外部入力をそのまま埋め込んだHTMLを開かないでください。

content directory外のfileは配信されません。共有assetも必ずcontent directory配下へ置いてください。

Troubleshooting

  • navigationが空になる: content directory内に隠しdirectoryとnode_modules以外の.html fileがあるか確認する。
  • documentが404になる: link先がcontent directory内にあり、大文字・小文字を含めfile名が一致するか確認する。
  • Mermaidがsourceのままになる: 利用projectでnpm install --save-dev mermaidを実行し、Viewerを再起動する。
  • Chartが表示されない: chart.jsのinstall、canvas ID、browser consoleを確認する。
  • 変更が反映されない: Viewerが起動中か、変更したfileが起動時に指定したdirectory配下にあるかを確認する。
