Authoring guide

These are the minimum rules for an LLM that generates or edits Spec HTML documents. Write the content directly in standard semantic HTML, then use the linter diagnostics to correct smaller mistakes.

Rules

  1. Make each file an HTML fragment with one root article. Set its lang attribute to the document's primary language. Do not add html, head, or body elements.
  2. Add exactly one h1 for the document title and choose standard HTML elements that match the content. Do not invent custom elements or components.
  3. Put important information—requirements, conclusions, and values—in the HTML text. Use scripts and canvases only to support that content.
  4. Write document links and asset URLs as relative URLs that remain inside the content directory.

Fix HTML typos

Use the fixer for unambiguous mistakes in tag names, attribute names, quotes, closing tags, closed attribute values, IDs, and local paths. It changes only HTML surface syntax and never rewrites prose, script content, or JavaScript in event-handler values. 

spec-html fix ./specs --check
spec-html fix ./specs --write

Format the document

After authoring, use the formatter to normalize indentation and line breaks. --check reports whether files differ without changing them; --write updates only files that need formatting. 

spec-html format ./specs --check
spec-html format ./specs --write

Full HTML documents are also accepted. Safe document wrappers and metadata are normalized to fragments, but conversion is refused when the head contains style, script, link, or base content, or when wrapper attributes affect rendering or behavior. The formatter does not invent semantic choices such as alt text, captions, headings, or elements.

Lint the document

You do not need to memorize every element rule. Run the linter after creating or editing a document and fix its errors. Improve warnings where appropriate, or treat them as errors in CI. 

spec-html lint ./specs
spec-html lint ./specs --warnings-as-errors

When a diagnostic is unclear, request the explanation for its rule ID:

spec-html lint --explain DOC001

Run all checks together

Use check to run the fixer, formatter, and linter in that order. The default run reports every stage without changing files. Add --fix to apply safe fixer and formatter changes before linting the result. 

spec-html check ./specs
spec-html check ./specs --fix

Stage selectors run only the requested combination. For example, use --fixer --lint for the fixer and linter, or --fixer --format for the fixer and formatter.

Minimal template

<article lang="en">
  <h1>Document title</h1>

  <section id="overview">
    <h2>Overview</h2>
    <p>The main point of the document.</p>
  </section>
</article>

Mermaid example

When a diagram is useful, put its source in pre.mermaid and describe it with a figure and figcaption. 

<figure>
  <pre class="mermaid">
flowchart LR
  Browser --> API
  API --> Database
  </pre>
  <figcaption>Request flow</figcaption>
</figure>
