Authoring guide

これは、Spec HTMLの文書を生成・編集するLLM向けの最小ルールです。本文は標準のsemantic HTMLで直接書き、細かな誤りはLinterの診断に従って直します。

ルール

  1. 各fileは、主言語を示すlang属性を持つ1つのarticleをrootにしたHTML fragmentにする。html、head、bodyは書かない。
  2. 文書の題名としてh1を1つ置き、内容に合う標準HTML要素を選ぶ。独自要素や独自componentは作らない。
  3. 要件、結論、数値などの重要な情報はHTML本文に書く。scriptやcanvasなどは、本文を補強するためだけに使う。
  4. 文書間linkとassetは、content directory内のfileを指す相対URLで書く。

HTMLのTypoを修正する

tag名、attribute名、引用符、閉じtag、閉集合のattribute値、ID、local pathの明白な誤りにはFixerを使います。FixerはHTML表層だけを変更し、文章、script本文、event handler属性値のJavaScriptは書き換えません。 

spec-html fix ./specs --check
spec-html fix ./specs --write

Formatterで整える

作成後のHTMLはFormatterでインデントと改行を統一します。--checkは変更せずに差分の有無を確認し、--writeは変更fileだけを書き換えます。 

spec-html format ./specs --check
spec-html format ./specs --write

full HTML documentも入力できます。安全なdocument wrapperとmetadataはfragmentへ正規化されますが、headにstyle、script、link、baseがある場合やwrapperに表示・動作へ影響する属性がある場合は変換されません。Formatterはalt、caption、見出し、semantic elementなど、内容の意味を選ぶ修正を行いません。

Lintで確認する

詳細な禁止事項や要素ごとの規約を覚える必要はありません。作成・編集の後にLinterを実行し、errorを修正します。warningも必要に応じて改善し、CIではerrorとして扱えます。 

spec-html lint ./specs
spec-html lint ./specs --warnings-as-errors

診断の修正方法が分からない場合だけ、rule IDを指定して確認します。

spec-html lint --explain DOC001

全ての検査を一括実行する

checkはFixer、Formatter、Linterの順で一括実行します。既定ではfileを変更せずに全ステージの結果を報告します。--fixを付けると、安全なFixerとFormatterの変更を適用してから結果をLintします。 

spec-html check ./specs
spec-html check ./specs --fix

必要な組み合わせだけを実行する場合は処理を選択します。例えばFixerとLinterは--fixer --lint、FixerとFormatterは--fixer --formatを指定します。

最小テンプレート

<article lang="ja">
  <h1>文書の題名</h1>

  <section id="overview">
    <h2>概要</h2>
    <p>文書の要点です。</p>
  </section>
</article>

Chart.jsの例

Chart.jsを使う場合は、canvasをfigureに入れてaccessible nameを付け、inline scriptからglobal Chart APIを呼び出します。JavaScriptが動かない場合にも内容を確認できるよう、正確な値は通常のHTMLにも残します。 

<figure>
  <canvas id="latency-chart" aria-label="versionごとのP95 latency"></canvas>
  <figcaption>P95 latency: 2.1 = 180 ms、2.2 = 220 ms、2.3 = 230 ms</figcaption>
</figure>

<script>
  new Chart(document.getElementById("latency-chart"), {
    type: "line",
    data: {
      labels: ["2.1", "2.2", "2.3"],
      datasets: [{ label: "P95 (ms)", data: [180, 220, 230] }]
    }
  });
</script>

Mermaidの例

Mermaidを使う場合だけ、図のsourceをpre.mermaidへ書き、figureとfigcaptionで説明を付けます。 

<figure>
  <pre class="mermaid">
flowchart LR
  Browser --> API
  API --> Database
  </pre>
  <figcaption>Request flow</figcaption>
</figure>
